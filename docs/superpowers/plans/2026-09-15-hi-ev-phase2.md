# Hi-EV Phase 2 — Presence + Status + Research + Drafting + Gmail/Calendar

> **Goal:** EV feels like a real assistant: richer status, cross-project briefs, web research with citations, Tier 1 drafting, Claude Code spawning, and read-only personal Gmail + Calendar ingestion.

## Order of work

The plan is intentionally sequenced so each feature builds on the previous one and can be demoed immediately after it lands.

### 1. NVIDIA NIM LLM client
**Why first:** All later LLM-powered features (research, drafting, summarization) need a single, tested client. NVIDIA NIM is OpenAI-compatible and uses the `nvapi-...` key you provided.

- Add `src/ev/llm/client.py` with a thin `LLMClient` wrapper.
- Support `EV_LLM_PROVIDER=nvidia` (default) and optional `anthropic` / `openai` fallback.
- Config: `EV_NVIDIA_API_KEY`, `EV_NVIDIA_BASE_URL`, `EV_LLM_MODEL`.
- Default chat model: `meta/llama-3.2-11b-vision-instruct` (verified working with the provided NVIDIA key; clean final answers).
- Add async `complete(messages, temperature=0.7, max_tokens=1024)` method.
- **Tests:** mock the HTTP call; assert request body and response parsing.

### 2. Richer `ev status <project>` — foundation polish
**Why second:** The existing `ev status` command already works live, but its output is thin. Making it genuinely useful is the highest-leverage next step and unblocks `ev brief`.

- Infer `Project.current_phase` from repo README / latest commits if unset.
- Include open issue count, open PR count, and recent notes in the summary paragraph.
- Add `MemoryStore` helpers: `count_open_issues(project)`, `count_open_prs(project)`, `recent_notes(project, limit)`, `list_active_projects()`.
- Update `StatusTool` / `build_status_summary` to consume them.
- Add CLI output formatting: one paragraph + optional `--json` flag.
- **Tests:** mock ingest rows for commits/issues/PRs/notes and assert the summary text contains counts.

### 3. `ev brief` — cross-project morning/now status
**Why third:** Once `ev status` is rich, aggregating it across all known projects is a small increment with big perceived value.

- Add `BriefTool` (T0) that calls `build_status_summary` for every active project and assembles a concise multi-project brief.
- Add CLI command `ev brief` and `POST /brief` API endpoint.
- Detect "stale" projects (no ingest activity in N days) and highlight them.
- **Tests:** seed multiple projects, assert brief mentions each and highlights stale ones.

### 4. Web research (`ev research <query>`) — read-only with citations
**Why fourth:** This is the first LLM-powered feature. It does not mutate anything, so it is safe to build before the action layer.

- Add `ResearchTool` (T0) using DuckDuckGo lite/HTML search via `httpx` (no API key, no Google dependency).
- Extract top-N result titles + snippets + URLs.
- Use the NVIDIA LLM client to synthesize a cited answer with source URLs embedded.
- Add `ev research "..."` CLI and `POST /research` API endpoint.
- Cache results in Redis if available; otherwise skip cache.
- **Tests:** mock DuckDuckGo HTML response; assert citations contain URLs. Mock LLM client for deterministic output.

### 5. Claude Code spawn (`ev work on <task>`) — first Tier 1 action
**Why fifth:** This bridges EV to the tool you already use. It is reversible and loud, perfect for T1.

- Add `WorkTool` (T1) that takes a project name + task description.
- Look up `Project.repo_path` (local checkout path).
- Build a context payload from recent commits/issues/notes and the task.
- Spawn `claude code` CLI as a subprocess in the repo directory with the prepared prompt.
- Log the spawn as an `Event` for audit.
- Add `ev work on "fix failing test in Phase 29" --project RoboCAD` CLI and `POST /work` API.
- **Tests:** mock subprocess spawn; assert command contains repo path and task context.

### 6. Tier 1 drafting tools
**Why sixth:** These are reversible writes: drafts, not sends.

- `DraftCommitTool` — read staged diff, draft commit message in your voice.
- `DraftPrTool` — read branch diff vs `main`, draft PR title + body.
- `DraftReplyTool` — draft an email reply from a few example snippets (no send; T1 because it writes a file).
- All three are T1, write to stdout or a draft file, and use the NVIDIA LLM client.
- Add CLI subcommands under a `ev draft` group.
- **Tests:** mock diff content / LLM response; assert output contains expected sections.

### 7. Personal Gmail + Calendar read-only ingestion (MUST for Phase 2)
**Why seventh:** You explicitly want this. It is high value and high risk, so we build it after the action layer is stable, and keep it strictly read-only + personal-only.

- Add `GmailIngestion` using Google OAuth2 credentials.
- Add `CalendarIngestion` for deadlines and pre-meeting prep.
- Add a new `Deadline` model/table for structured deadlines.
- Populate deadlines from calendar events.
- Add `ev calendar prep <time>` command.
- **Gate:** require explicit user opt-in via `.env` (`EV_GOOGLE_ENABLED=true`) and OAuth JSON in a secrets dir. Refuse to run if `EV_PERSONAL_ONLY` is false.
- **Tests:** mock Google API responses; assert only personal labels/calendars are ingested and no writes occur.

### 8. Voice skeleton — deferred to Phase 5+
**Why not in Phase 2:** Cross-platform hotkey/tray integration is finicky and not required for the core demo. We keep LiveKit/RoomKit as a Phase 5+ research item. A research doc is already saved at `docs/superpowers/research/2026-09-15-nvidia-api-livekit-voice.md`.

## Acceptance criteria for Phase 2

- `ev status RoboCAD` returns a paragraph with phase, latest commit, open issue/PR counts, and recent notes.
- `ev brief` returns a multi-project status in under 5 seconds.
- `ev research "attention budgets in robot perception"` returns a cited summary with URLs (powered by NVIDIA LLM).
- `ev work on "fix failing test in Phase 29" --project RoboCAD` spawns Claude Code in the RoboCAD directory with context.
- `ev draft commit --project RoboCAD` drafts a commit message from staged changes.
- Gmail + Calendar ingestion runs read-only, gated by `.env`, and populates deadlines.
- All new tools carry a `tier` attribute and log T1 spawns/drafts to the `Event` table.
- `pytest` passes with no new warnings; `ruff check` clean.

## Risk mitigations

- **No work data:** every new connector inherits the `personal_only` guard; research and drafting tools never ingest work accounts.
- **Tier discipline:** all drafting/spawning tools are T1 (reversible). No T2/T3 actions in Phase 2 except possibly calendar prep (read-only).
- **API cost caps:** NVIDIA free tier is the default. Anthropic/OpenAI are optional fallbacks. LLM calls use max tokens and timeouts.
- **Secrets:** new keys live in `.env` only.
- **Gmail/Calendar safety:** read-only scopes only; no send, no create, no delete.
