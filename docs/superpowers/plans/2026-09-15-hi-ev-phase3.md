# Hi-EV Phase 3 — Memory + Deadlines + Alerts + Pre-Meeting Prep

> **Goal:** EV stops being reactive and starts remembering obligations, surfacing what matters before it is too late, and prepping you for meetings automatically. Phase 3 adds structured memory tables, a deadline watcher, proactive alerts, and pre-meeting prep — all still local-first and personal-only.

## Order of work

The sequence is designed so every feature can be demoed the moment it lands, and so the Google-sensitive pieces are isolated behind explicit credentials.

**Why first:** Make sure the live Phase 2 code and daemon are solid before adding new tables.

- Confirm `python -m pytest` is green and `evd` starts cleanly.
- Confirm `.env` has `EV_NVIDIA_API_KEY`, `EV_GITHUB_TOKEN`, and repo path env vars.

### 1. Structured memory schema
**Why first:** Everything later (deadlines, alerts, prep) reads from these tables. Build the schema before the watchers.

- Add models:
  - `Deadline` — title, due_at, project_id, source (github/calendar/note/manual), priority, status (open/done/snoozed), snooze_until.
  - `Person` — name, email, source, notes, last_contact_at.
  - `Obligation` — description, project_id, owed_to_person_id, due_at, status.
  - `Decision` — topic, decision_text, rationale, made_at, project_id.
  - `Event` (audit log) — already exists; extend with `action_tier` and `undo_payload`.
- Add async Alembic migration (or SQLAlchemy create-all for local SQLite) under `src/ev/db/migrations/`.
- Add `MemoryStore` helpers: `upsert_deadline`, `list_deadlines`, `count_overdue`, `list_people`, `upsert_person`, etc.
- Add idempotency constraints: `(source, source_id)` on Deadline/Person/Obligation where applicable.
- **Tests:** assert schema creation, upsert idempotency, query helpers.

### 2. Google OAuth production setup
**Why now:** Real Gmail/Calendar data is the highest-value input for deadlines and prep, but it requires a credential file we cannot create programmatically.

- Add `docs/superpowers/setup/2026-09-15-google-oauth.md` with exact steps:
  1. Go to [Google Cloud Console → APIs & Services → Credentials](https://console.cloud.google.com/apis/credentials).
  2. Create a **Desktop app** OAuth 2.0 Client ID.
  3. Download `client_secret_*.json`, rename to `credentials.json`, place at `C:/Users/point/projects/Hi-EV/secrets/credentials.json` (or path in `.env` via `EV_GOOGLE_CREDENTIALS_PATH`).
  4. Enable **Gmail API** and **Google Calendar API**.
  5. Run `python scripts/google_auth.py` to perform the browser flow and save `token.json`.
- Update `src/ev/ingestion/google_auth.py` to support Desktop app flow with local redirect (`http://localhost:8080` or `urn:ietf:wg:oauth:2.0:oob` fallback).
- Store `token.json` in `secrets/` (gitignored).
- Add `.env` flags:
  - `EV_GOOGLE_ENABLED=true`
  - `EV_GOOGLE_CREDENTIALS_PATH=secrets/credentials.json`
- **User action required:** create the Google Cloud project and download `credentials.json`. EV will not attempt Gmail/Calendar ingestion until both the file and flag are present.

### 3. Gmail + Calendar ingestion enabled
**Why after OAuth:** Once credentials exist, the existing Phase 2 connectors run for real.

- Run `python scripts/seed_demo.py --google` (or a new `scripts/sync_google.py`) to:

  - Ingest Calendar events into `Ingest` and derive `Deadline` rows for events with deadlines or meetings.
  - Extract `Person` rows from email participants and meeting attendees.
  - Extract `Obligation` rows from flagged/starred emails and calendar action items (heuristic).
- Add `personal_only` checks: refuse to ingest calendars/emails labeled as work domains from a configurable blocklist.
- **Tests:** mock Google API responses; assert only personal calendars are ingested; assert no writes are sent back to Google.

### 4. Deadline watcher
**Why fourth:** With deadlines in the database, EV can now answer "what is slipping?"

- Add `DeadlineWatcherTool` (T0 read-only).
  - Scans `Deadline` and `Obligation` tables.
  - Computes urgency score: overdue > today > this week > future.
  - Filters by project if requested.
- Surface deadlines in `StatusTool` and `BriefTool` output.
- Add `ev alerts` / `POST /alerts` endpoint that returns the top-N urgent items.
- Add `ev deadline list [--project X] [--overdue]` CLI.
- **Tests:** seed deadlines with known dates; assert watcher ranks overdue first; assert brief mentions an overdue item.

### 5. Proactive alert loop
**Why fifth:** EV should speak first. A lightweight scheduler inside the daemon checks for new urgent items and emits a digest.

- Add a background `alert_loop` coroutine to the daemon (`src/ev/daemon/daemon.py`) using `asyncio.sleep` polling every 15 minutes.
- On each tick:
  - Run `DeadlineWatcherTool`.
  - Compare results to last emitted digest (store in `Event` or a small state file).
  - If new urgent items appear, log/print a one-line alert summary.
- Respect:
  - Kill switch (`EV_KILL_SWITCH=true` → pause loop).
  - Quiet hours (`EV_QUIET_START` / `EV_QUIET_END`, default 22:00–08:00).
  - Minimum alert interval (`EV_ALERT_INTERVAL_SEC`, default 900).
- Add `ev alerts --digest` to force an immediate digest.
- **Tests:** mock the clock and watcher; assert no alert emitted during quiet hours; assert alert emitted on new overdue item.

### 6. Pre-meeting prep
**Why sixth:** This is the first feature that synthesizes calendar + memory + project context into a useful artifact.

- Add `PrepTool` (T0 read-only).
  - Input: meeting title and start time (from calendar event or manual CLI).
  - Gather:
    - Calendar event details and attendee `Person` rows.
    - Recent notes tagged with relevant project.
    - Latest `ev status <project>` summary.
    - Any unread emails from attendees.
    - Open issues/PRs related to the meeting topic (search by keyword).
  - Use NVIDIA LLM to synthesize a 3-bullet agenda + 2 suggested talking points + open questions.
- Add CLI:
  - `ev prep "RoboCAD sync" --project RoboCAD --time "2026-09-20T10:00:00"`
  - `ev prep today` to prep all meetings in the next 24 hours.
- Add `POST /prep` endpoint.
- **Tests:** mock calendar/note/email data; assert prep output contains agenda bullets and mentions an open issue.

### 7. (Stretch) Cross-project obligation map

- Add `ObligationMapTool` that returns:
  - Who owes you something.
  - Who you owe something to.
  - Projects with the most overdue obligations.
- Surface in `ev brief`.
- **Tests:** seed obligations; assert map contains correct directional counts.

## Risks and decisions

| Risk | Mitigation |
|------|------------|
| Google OAuth scope/privacy | Read-only scopes only (`gmail.readonly`, `calendar.readonly`). Token stored locally. User can revoke from Google Account any time. |
| Work data bleed | Same `personal_only` blocklist used in Phase 2; calendar/email domains in the blocklist are silently skipped. |
| Alert noise | Quiet hours, minimum interval, and per-deadline snooze. Tuning defaults in `.env`. |
| Local SQLite scaling | Schema uses the same SQLAlchemy models that already support Postgres; switch by setting `EV_DATABASE_URL`. |
